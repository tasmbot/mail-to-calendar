# mail-to-calendar

Python-функция для Yandex Cloud Functions: читает непрочитанные письма из отдельной папки Яндекс.Почты и создаёт события в календаре iCloud через CalDAV.

Поддерживаются:

- вложения `text/calendar` и файлы `.ics`;
- текстовые и HTML-уведомления о заданиях Moodle-подобного формата;
- несколько заданий в одном письме;
- события на весь день или на время дедлайна;
- повторный запуск без дубликатов;
- диагностика в JSON-ответе функции.

Схема работы: Яндекс.Почта (IMAP) → Yandex Cloud Function → iCloud Calendar (CalDAV).

## Как обрабатываются письма

Функция ищет только `UNSEEN` в указанной папке. Письмо загружается через `BODY.PEEK[]`, поэтому само чтение не устанавливает флаг `Seen`.

Письмо помечается прочитанным только после успешного создания всех его событий. Если парсер или CalDAV вернул ошибку, письмо остаётся непрочитанным и будет повторно обработано при следующем запуске. Неизвестные типы писем также остаются непрочитанными.

Для заданий UID строится из Moodle `id` в ссылке, а при его отсутствии — из названия, курса и даты. Для `.ics` используется UID из вложения. При ответе iCloud `412 Precondition Failed` функция читает существующий ресурс и проверяет UID, прежде чем считать событие уже созданным.

## Переменные окружения

Обязательные переменные:

| Переменная | Назначение |
|---|---|
| `YANDEX_EMAIL` | Адрес Яндекс.Почты |
| `YANDEX_PASSWORD` | Пароль приложения Яндекса для почты |
| `ICLOUD_EMAIL` | Apple ID / адрес iCloud |
| `ICLOUD_PASSWORD` | Пароль приложения Apple |

Дополнительные переменные:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `TARGET_MAILBOX_NAME` | `iCloud` | Папка Яндекс.Почты с обрабатываемыми письмами |
| `TARGET_CALENDAR_NAME` | `Учеба` | Имя календаря iCloud |
| `ASSIGNMENT_SUBJECT_PATTERN` | `У вас есть задания, которые нужно сдать через` | Подстрока темы для писем с заданиями |
| `ASSIGNMENT_ALL_DAY` | `true` | `true` — событие на весь день; `false` — использовать время из письма |
| `DEADLINE_TIMEZONE` | `Europe/Moscow` | IANA-часовой пояс для времени дедлайна |

Не добавляйте пароли в код, `.env`, архив функции или Git. Храните их только в переменных окружения/секретах Yandex Cloud. Для Яндекса и Apple нужны пароли приложений, а не основные пароли аккаунтов.

## Подготовка почты и календаря

1. Создайте в Яндекс.Почте отдельную папку, например `iCloud`, и настройте правило перемещения нужных писем в неё.
2. Разрешите доступ почтовых клиентов по IMAP и создайте пароль приложения в Яндекс ID.
3. Создайте целевой календарь в iCloud, например `Учеба`.
4. Создайте пароль приложения Apple на странице управления Apple Account.

## Установка в Yandex Cloud Functions

1. Склонируйте репозиторий или скачайте `index.py` и `requirements.txt`.
2. Создайте функцию со средой Python 3.12.
3. Загрузите оба файла в корень версии функции.
4. Укажите точку входа `index.handler`.
5. Установите таймаут не менее 60 секунд и память 128–256 МБ. При большом числе писем увеличьте таймаут.
6. Добавьте обязательные и, при необходимости, дополнительные переменные окружения.
7. Создайте Timer Trigger. Например, запуск каждые 6 часов. Учитывайте, что часовой пояс cron задаётся настройками сервиса Yandex Cloud, а не `DEADLINE_TIMEZONE`.

Зависимости устанавливаются Yandex Cloud автоматически из `requirements.txt`.

## Локальная проверка

Требуется Python 3.12 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m py_compile index.py
```

Для реального локального запуска задайте переменные окружения и вызовите обработчик:

```bash
python3 -c 'import index; print(index.handler({}, None))'
```

Команда подключится к реальным аккаунтам и может создать события. Для безопасной проверки парсера импортируйте и вызывайте `parse_assignment_email` или `generate_ics_for_assignment` отдельно.

## Формат уведомления о заданиях

Парсер рассчитан на русский текст примерно такого вида:

```text
Необходимо сдать до воскресенья 16 ноября 2026

- Задание по теме 2 (самостоятельное) в курсе Нереляционные базы данных (26/27_ИД)
  Срок: 11:59 PM
  https://edu.example/mod/assign/view.php?id=2337177
```

Допускаются HTML-only письма, Markdown-выделение `**`, переносы строк, маркеры `-`, `*`, `•`, время в 12- и 24-часовом формате и несколько заданий.

## Ответ и диагностика

Функция возвращает JSON со счётчиками:

- `processed_emails` — успешно обработанные письма;
- `created_events` — созданные события;
- `existing_events` — подтверждённые существующие события;
- `failed_emails` — письма, оставленные непрочитанными из-за ошибки;
- `diagnostics` — этапы обработки и краткие сообщения об ошибках.

HTTP `200` означает, что ошибок писем не было; `207` — часть писем не обработана; `500` — ошибка конфигурации, подключения или обнаружения календаря. Ответ не содержит пароли и полные тела писем.

## Ограничения

- IMAP-сервер и CalDAV endpoint сейчас зафиксированы для Яндекса и iCloud.
- Парсер уведомлений ориентирован на описанный русский шаблон; изменение текста отправителем может потребовать обновления регулярных выражений.
- Обрабатываются только непрочитанные письма в одной папке. Неподдерживаемое письмо будет оставаться непрочитанным, пока его не переместить или не пометить вручную.
- Вложение `.ics` должно содержать `UID`. Подписи, отмены (`METHOD:CANCEL`), обновление уже существующего события и сложные серии повторений специально не интерпретируются — файл передаётся iCloud как есть.
- Один запуск последовательно обрабатывает все найденные письма и может упереться в таймаут функции при большом объёме.
- Стабильный алгоритм UID предотвращает новые дубликаты, но не сопоставляет события, которые были созданы старыми версиями с другим UID.
- Реальные интеграционные тесты требуют учётных данных Яндекса и Apple; в репозитории автоматических тестов нет.

## Безопасность

- Используйте отдельные пароли приложений и периодически меняйте их.
- Не выводите значения секретных переменных в логи.
- Ограничьте доступ к функции и её журналам.
- Если секрет когда-либо попал в Git, отзовите его — удаления строки из последующего коммита недостаточно.
